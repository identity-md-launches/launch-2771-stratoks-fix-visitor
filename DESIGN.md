# STRATOKS interface system

## Overview

STRATOKS is an observer for a persistent 280×280 learning world. A bright, painted isometric scene fills the screen; compact charcoal/moss controls use warm gold for the primary action and selection. The original golden scalloped, leaf-crowned species is used consistently in world sprites, portraits, logo, favicon and share image. The fresh review starts a clearly labeled isolated engine demo; recorded and owner/live sources keep separate labels.

Canonical source: `web/src/expanse/expanse.css`, its later `living.css` additions and final `visitor-wallet.css` overrides, `App.tsx`, `Map.tsx`, `Inspector.tsx`, `appearance.ts`, `worldRenderer.ts`, `ground.ts`, `projection.ts`, `surface.ts`, `AgencyEvidence.tsx` and `VisitorWallet.tsx`. Reuse the existing UI and projection system. The retired `#settlement` route stays unavailable. The current HUD has optional visitor authentication, using only the current Expanse API.

## Typography

The local Manrope Variable WOFF2 is loaded through `web/src/styles.css` and the existing `@fontsource-variable/manrope` dependency. The UI uses weights 400, 600 and 800 where the incumbent system calls for them. Georgia / Times New Roman / serif at 400 carries the world title and resident name. The original SVG wordmark uses system Georgia at 700 as artwork. No remote font is requested.

The six-size scale is **12, 14, 16, 20, 24, 32 px**. Captions/data use 12; controls and dense prose 14; inputs/section headings 16; compact headings 20; resident names and the phone world title 24; the desktop world title 32. Line height is 1.5–1.6 for prose/data and 1.15–1.25 for headings. Large-title tracking is −0.02em; body tracking is natural. Changing values use tabular numerals. Names, resource keys and IDs wrap instead of being truncated. Mobile inputs/selects remain 16px.

## Layout

The application occupies `100dvh` with a `100vh` fallback and safe-area insets. The map is the main content; the title and “Find residents” action float over it. There is no marketing page above the world. Desktop rows are a 68px header, 34px status strip, flexible map/workspace and 34px footer. Controls use 24–28px outer insets, 8–12px local gaps and 16–24px group spacing. Buttons are normally 40–44px; compact landscape controls use 32–40px widths with distinct spacing.

Above 700px, the optional resident/records/settlement inspector takes 352px (368px above 1100px). At 1000px and below the header becomes compact. At 700px and below the rows become 60/32/flexible/30px plus safe areas; the inspector becomes a separately scrolling bottom sheet occupying 44% of the workspace. The remaining map is its own resized viewport, preserving selection/follow. When desktop map width changes, the camera span changes in the same proportion so residents retain their screen size; a phone sheet changes height only and keeps its zoom. The default phone span is 9.5 rather than 22 on desktop, with actual camera bounds/aspect determining the final clamp.

At widths ≤360px, logo/control spacing tightens. At phone heights ≤720px, navigation is a horizontal rail above the independent zoom row. An expanded atlas uses the title's space, temporarily hides the scene heading/notice, and closes after a pointer or arrow location is chosen. With an open inspector on a short map it also temporarily hides the rail; the atlas close toggle and header remain available. This avoids covered navigation targets. In 540–700px short landscape layouts the title/actions share a row and zoom starts after the wider navigation rail. Notices and follow status otherwise flow with an 8px gap; they do not assume a single-line height.

The checked browser sizes are 320×568, 390×844, 667×375, 844×390, 851×700 and 1440×900. The design probe also checks 320/390/1440-wide first screens. Actual browser results are in the validation artifact. These are emulated viewports, not physical safe-area or native-zoom certification.

## Elevation & Depth

HUD panels use opaque moss surfaces and restrained transparent shadows. Borders communicate fields, list divisions, selection and construction/evidence structure; ordinary raised surfaces do not combine a border and shadow. Terrain, ground wear, ground-depth-sorted sprites and foreground cliff faces, map controls, inspector and native modal form the stacking order. Surface lift is derived from authoritative tile kinds (water 0; soil 0.18; snow 0.26; dune 0.32; rock 0.42; cliff 1.35 half-tile units). Equal-height neighbours share faces; exposed drops form actual polygons. `surface.ts` owns the same geometry for drawing, picking and foot anchors. These visual heights do not change movement rules. World-corner focus is clamped to valid tile centres, allowing the necessary off-world space. World art anchors are ground contacts, not image centers.

The canvas focus ring is inset so clipping cannot remove it and uses a two-color charcoal/gold perimeter. Other controls use a three-pixel focus outline with three-pixel offset. Decorative compass, light/ground details and sprite shadows do not intercept pointers.

## Shapes

Buttons and fields use 8px radii; tool groups 10–12px; the scene title keeps a 3px leading corner with 18px outer corners; the native modal uses 18px. The mobile inspector uses 16px top corners. Tile evidence has a 12px radius; its minimap coordinate hit surface is square and never scales/translates during a press. Portraits sit on recessed round surfaces. Transparent world silhouettes remain separate from UI surfaces and never become rectangular entity cards.

## Components

- **`WorldMap` / `MiniMap` (`Map.tsx`)**: pointer drag/pinch, wheel zoom, keyboard arrows and +/−, resident picking, exact terrain evidence, home navigation, chunk atlas and viewport polygon. The roster provides a keyboard selection alternative to canvas picking. The atlas's Enter/Space activation preserves camera position; arrows select an explicit chunk. `TileEvidence` shows received terrain, surface lift, nodes, crops, ruins, sites, materials, observer stores and tick. It is a native top-layer dialog with an independent scroll body and nonshrinking Close header. Its 360px width and maximum viewport dimensions subtract safe-area insets plus 32px. Enter inspects map centre; Close/Escape restores canvas focus. Background HUD is inert while the dialog is open.
- **`projection.ts` / `surface.ts`**: shared base transforms for camera/zoom/minimap plus elevation projection, top/face meshes and bounded reverse picking. Reuse them; no independent art-only pick coordinates. Viewport requests include a four-tile halo and stay within 96×96.
- **`WorldRenderer` / `appearance.ts`**: culling, foot-depth sorting, state-gated sprites and movement interpolation for adjacent confirmed positions in consecutive engine ticks. Missing intermediate paths snap. Loads require matching contents; fishing requires the engine state/phase and line; sleep requires actual sleep; tool-work poses additionally require a held supported work tool. Fire requires an existing record. No invented speech, emotion, encounters or scenery affects decisions.
- **`GroundCache` (`ground.ts`)**: one DPR≤2 viewport composition and at most 384 68×128 tile rasters (~12.75 MiB RGBA). Raster keys include terrain, biome, lift, adjacent drops and eight texture variants; the viewport signature excludes tick. Changed camera/terrain recompose; unchanged terrain across simulation ticks is reused. Foreground cliffs also enter the entity depth queue. `shared/relief.js` defines derived visual heights. Supplementary face textures are clipped inside those real polygons, across every biome.
- **`WornPaths` / `settlementWear` (`paths.ts`)**: soft earth approaches to reported shelters and up to 256 adjacent travel segments observed in the viewer. Water, cliffs, blocking nodes and diagonal corner cuts are excluded. The previous resource-bearing texture is removed; wear has no engine state or pathfinding effect.
- **`CreatureInspector` (`Inspector.tsx`)**: identity, needs, actual activity/phase/progress, weight/capacity, target and tools, Follow, evidence download and native expandable Goals/Signals/Plans/Perception/Learning panels. `AgencyEvidence.tsx` keeps goals, strategies, local signal associations, recent response steps and individual trust in bounded lists. Unknown capabilities are omitted on older server frames. `StoreKnowledge` explicitly separates never-visited, inherited-unverified and stale visited stock. Individual traits and relationships have their own disclosure. Predictions, uncertainty and outcomes remain separate. Pending/missing data has explicit recovery copy; recorded evidence keeps its tick label. Progress does not promise success. The roster and inspector share one scroll body (`.exp-panel-scroll`): changing panel mode or resident resets it to the top before the resident heading takes focus, while live refreshes of the same inspector keep the reader's scroll position.
- **Residents / records / settlements (`App.tsx`)**: one responsive side surface, actual search results and empty-state clear action, bounded event history and real world totals. Settlement rows are computed from actual API structure records, grouped spatially for navigation, filtered by biome. Selecting a row moves the observer only.
- **`Modal` (`web/src/Modal.tsx`)**: native dialog with inert background, Tab containment, Escape and focus return. World URL form uses native validation, a visible label, inline guidance/error and focus on invalid input. Help links the supplied model sheet and explains source/knowledge scopes.
- **Buttons**: `.exp-button.primary` (gold fill), `.exp-button` (moss), `.exp-icon` (named icon) and `.exp-text-button` (compact action). Hover, focus, pressed, pending and disabled states are explicit. Transitions name their properties and use 150 ms or less; press scale is 0.96 only with no reduced-motion preference. Minimap hit testing overrides both scale and transform so the coordinate basis is stable during a press.
- **`Portrait` / `drawSprite` (`art.tsx`)**: local character atlases for UI and world. The supplemental kneeling actor is extracted from `[0,30,209,250]` of the supplied sheet with foot anchor `[110,222]`; the nominal 209px row would clip its body. Four 40×64 rock-paint patches become a 160×64 face strip. Complete used derivatives are local; unsupported wheat, cookware, vessels and paired actors are omitted. `web/public/art/manifest.json` gives the 68 cell rectangles, pivots, input hashes and license. `logo.svg`, `favicon.png`/`.svg`, `share-world.jpg` and `model.webp` all use the leaf-crowned species. The visitor wallet uses the same local line-icon set as the rest of the HUD; provider-controlled HTML and remote icons are never rendered. The body draw width is 2.65 half tiles (visible silhouette about 1.25); completed shelters use 4.6, making the original art less oversized. The kneeling pose uses 1.5 with its tighter crop, keeping visible scale consistent.

## Do's and Don'ts

The visitor account surface reuses the same palette, local Manrope 12/14px body roles, 400/600 weights, native `Modal` with its inherited Georgia 24px/1.2 title, and local `Icon` set. `visitor-wallet.css` loads last. Use `.exp-wallet-control` only in header utilities: 44px minimum height, 8px radius, moss fill, visible focus inherited from `.exp-app`. Its compact label appears at 700px and below; logo width becomes 136px (104px at 360px and below), and the duplicate Settings icon is hidden while Choose world and Help remain. Header geometry never enters the map's control zones or resizes the simulation viewport during sign-in. Desktop shows short address plus state; the dialog keeps the full wrapping address selectable.

`VisitorWallet` takes `backendUrl`, `worldId`, `open`, `onOpen`, `onClose`. The parent owns the shared modal slot, so wallet, Help and Choose world cannot open overlapping dialogs. `.exp-visitor` uses a 16px vertical gap; `.exp-visitor-feedback` groups status and its explanation with a 12px gap. Provider rows use 12px inset, 52px minimum height and an 8px radius. Status distinguishes disconnected, connected, signing, checking, verified, expired and unavailable. A retained credential whose check failed is **Session unconfirmed**, with **Last confirmed visits** rather than a fresh verification claim; the header reads **Check**. The full address wraps and stays selectable.

The dialog has one atomic polite live region containing status and the single reason. The closed-dialog header announcer is absent while the dialog is open, avoiding both duplicate announcements and reliance on inert background content. Connection, capability and signature errors replace that reason instead of adding another unavailable explanation. A primary gold sign-in action has a nearby reason for every disabled state; Cancel attempt, server sign-out and retry remain distinct. Retry is enabled during ordinary backoff; a server `Retry-After` cooldown shows a disabled **Retry scheduled** control. Server-confirmed logout, pending offline revocation and expiry have distinct text. The native privacy disclosure names retention of inactive visitor records and untested-provider limits. No new animation, font, type size or color is added.

Final 320/390/768/1440px wallet and world screenshots are in `artifacts/visitor-recovery/`. At 390px the scene, Find residents and Connect are visible on the first screen. Solid modal text/background pairs measured 7.53:1 (gold), 7.31:1 (secondary), and 11.01:1 (primary), all against `#28362d`; see the raw existing-browser report. The first-screen probe leaves image/canvas contrast unmeasured. Physical devices and screen readers remain unverified.

The isolated static preview still discovers wallets and permits a normal connection, explicitly labeled **Connected · not signed in**. It has a null auth backend and never offers a sign-in action or requests a signature/session. Choosing a real world recreates that controller and checks the selected service's capabilities. This distinction is visible in `artifacts/visitor-auth/static-connected.jpg`; no preview account or authentication is fabricated.

Logout copy distinguishes no active local session from an acknowledged server revocation. Reload forgets the tab’s credential; it does not confirm server logout. Both the verified reason and privacy disclosure advise signing out before reload and disclose server expiry/restart as the fallback. `session_store_full` has its own recovery text: sign out in another signed-in tab or wait for existing sessions to expire. A request cooldown cannot promise capacity. Keep those messages separate when reusing the account component. The reload-copy revision preserves all tokens, type roles, spacing, controls and breakpoints above; its current rendered checks are in `artifacts/visitor-recovery/revision/VALIDATION.md`. The preceding integration review remains at `artifacts/visitor-recovery/VALIDATION.md`.

The signature prompt allows 60 seconds for reading, separately from 10-second network/connection deadlines. A visible Cancel attempt action remains available; timing does not animate or change the map. Reuse this separation when adding another signature-only visitor flow.

Start an added observer view with these tokens, button classes, native disclosures and the existing side-panel pattern. Keep the world visible, put the main action on the first phone screen, and state the actual data source. Add explicit pending/empty/error states next to their controls. Reuse the local font and the shared projection.

Render only engine-supported objects and activities. Read per-resident evidence for knowledge, never the observer atlas. Preserve the owner world/save identity; the demo checkpoint is exclusively private. Keep representative load art separate from exact quantity text. Do not add unobserved resources, prewritten tours, decorative routes, fake events, thoughts or fabricated “live” data. Visitor identity belongs only in the private account dialog, never in public world evidence. Document supplied art and performance limits in validation rather than claiming a rig, device test or independent approval that does not exist.
